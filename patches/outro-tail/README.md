# 片尾保留缓冲补丁

本 fork 的目标是为原生播放 API 的片尾跳转提供**至少**指定秒数的媒体尾部缓冲，而不是把所有片尾标记强制移动到同一个位置。

## 根因

上游 `TimeAdjustmentHelper.AdjustIntroTimesAsync` 在原始终点到达 EOF 吸附阈值时直接使用媒体时长，扣减 `IntroEndOffset` 的逻辑却位于另一个分支。阈值为零也不能避免恰好到 EOF 的吸附。候选组合还可能把接近扫描窗口结束的片尾候选延伸到窗口结束。

本补丁不改这些原始分析规则，而是在所有提供者已汇总的播放响应上加保护，覆盖旧片段、新扫描结果及其他提供者。

## 规则与 90 秒示例

配置读取自现有 `IntroEndOffset`；**设置为 5 才表示 5 秒保护**，上游配置默认值不是自动启用 5 秒的新开关。

```text
cap = max(0, RunTimeTicks - IntroEndOffset × 10,000,000)
returnedEnd = min(originalEnd, cap)
```

以媒体总长 **100 秒**、`IntroEndOffset=5` 为例：

| 原片尾标记终点 | 返回终点 | 含义 |
| --- | --- | --- |
| 100 秒（EOF） | 95 秒 | 留下最后 5 秒 |
| 98 秒 | 95 秒 | 原本只有 2 秒，扩充为 5 秒 |
| 103 秒（超过片长） | 95 秒 | 不向客户端返回超片长的片尾跳转 |
| 95 秒 | 95 秒 | 已满足保护，不重复扣减 |
| **90 秒** | **90 秒** | 已留下 10 秒，不反向延长跳过范围 |

“90 秒不处理”不是忽略某种 90 秒长的视频，也不是认为最后 10 秒一定是预告/彩蛋。它只是保守地**不扩大原有跳过区间**：没有证据证明 90–95 秒是可跳过内容，就不把跳转终点从 90 秒推迟到 95 秒。否则可能跳过额外的正片、彩蛋、预告，或已由原分析 offset 留下的片尾内容。

如果希望“每个原始片尾终点再减 5 秒”，那是另一种规则，例如 90→85 秒；它不是本补丁的规则，且可能再次扣减分析阶段已经应用的 offset。

## 精确作用范围

- 仅 `Jellyfin.Api.Controllers.MediaSegmentsController.GetItemSegments` 的成功原生播放 `GET /MediaSegments/{itemId}`。
- 仅 DTO 中的 `Outro`（片尾）；不按提供者或 segment ID 筛选。
- 原结束点早于 cap 时不延长；被改 DTO 与包装创建副本，不改共享输入对象。
- 裁剪后 `End <= Start` 的片尾只从该播放响应排除，不删除存储行。
- 保留 segment ID、item ID、类型、起点和分页元数据；单纯裁剪不减少总记录数。
- `Intro`、`Recap`、`Preview`、`Commercial` 与编辑 GET/写接口不变。
- 不依赖首集过滤开关，不执行 FFmpeg，不写数据库，不更改分析/投影/提供者。
- 配置 <=0、插件不可用、时长未知/无效、非成功/未知响应透传；不能声称这些情况也保证尾部缓冲。

## 验证范围

2026-10-13 的本地验证：

- 同一注册管线契约测试：未加保护时 2 通过、3 失败；补丁后 5/5 通过。
- 最终定向测试 **261/261**：新增 67 项与既有回归 194 项；0 失败、0 跳过。
- 包含 ticks 精度、溢出边界、多片段、别名不变、计数、5→0→8 配置对象替换、精确 GET 匹配、错误响应、下游异常、首集过滤两种顺序及编辑/hash 等回归。
- 实际 Jellyfin 12.1 宿主 DLL 的本地 smoke 执行真实控制器的匹配、DI 创建、真实 DTO/QueryResult 裁剪和 JSON 序列化；不是仅反射列出类型。
- 保留默认 Credits 固定分析 hash `353008E48A5F559E`。这是测试默认值，**不是某个服务器当前 hash 的声明**。
- 没有跑完整媒体分析测试套件，没有由此完成群晖整体启动或 Infuse 实际播放验收。

所有公开测试数据均是合成夹具；私人配置、真实媒体记录、宿主 DLL 和原始私人日志不入此仓库或 Release。

## 本地构建与定向复测

需要 .NET 10、Node/pnpm。依赖锁包含已验证的 Jellyfin `12.0.0` 编译输入，不自动改为新 Jellyfin 包。

```bash
bash patches/outro-tail/build.sh
```

脚本构建前端嵌入资源、进行 locked restore、运行同一组 261 项定向测试，并输出 DLL、日志和 TRX 到被 Git 忽略的 `artifacts/outro-tail/`。显式覆写程序集版本为 `12.0.4.0`，避免上游源码标签中的 `12.0.3.0` 项目值误导普通构建。

若有合法取得的**实际宿主程序集**，还可提供目录运行类型兼容 smoke：

```bash
HOST_REFERENCE_DIR=/path/to/actual-jellyfin-dlls \
  bash patches/outro-tail/build.sh
```

未提供宿主目录时，脚本只运行编译与定向测试，并明确跳过真实宿主 smoke。禁止把 NuGet 的同名 Jellyfin 12.0 DLL 当成实际宿主输入；缺少实际宿主依赖时 smoke 失败，不自动替代。

## Release 与部署边界

Release 中仅提供插件 DLL、明确的非官方说明与 SHA256；不附宿主 DLL。上游原有工作流仍保留在历史里，但本 fork 目前关闭 Actions 自动运行：那些工作流会自动改版、发布滚动预发布，并包含镜像广播，不用于本补丁的手动版本追踪。没有建立自动更新 manifest，也不会向上游自动提交 PR 或发布到官方镜像。

在自己的维护窗口中部署前，先备份原插件文件/配置、记录校验与权限，确认没有活跃播放，评估官方自动更新覆盖补丁的风险。保持 `IntroSkipper.dll` 文件名；不要把 `MediaBrowser.*`/`Jellyfin.*` DLL 放进插件目录。启动失败时只回退插件文件/配置，不用整库恢复覆盖新的观看数据。

旧片段通过同一播放出口即可受保护，不要求为本补丁全库重扫。但是原有库更新、配置变化、缺少分析完成记录等仍可能触发正常后台分析；不把“补丁不改 hash”解释成“后台永远不会重新分析”。

Infuse/其他客户端可能缓存旧标记、采用独立第三方标记、自动跳过 `Preview` 或自行切下一集。它们不由仅保护片尾响应的补丁直接控制。实际验收需要客户端重新加载条目，检查它使用的真实请求、跳转位置、最后部分正常播放与观看事件；API/type smoke 成功不能代替这些验收。
